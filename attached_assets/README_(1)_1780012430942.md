## Replit → GitHub → Cloudflare Pages

### 1. Replit setup
- Upload these three files to your Replit project
- No build step needed — this is pure static HTML
- In Replit, leave **Build command** blank
- Set **Output directory** to `.` (root)

### 2. Connect Replit to GitHub
- In Replit: Version Control → Connect to GitHub → push to a repo
  (e.g. `realtor510/school-guide` or add to your existing site repo)

### 3. Cloudflare Pages settings
If adding to the **existing realtor510.com Cloudflare Pages project**:
- Just add these files to the existing repo at the root level
- Cloudflare will pick them up on next deploy

If creating a **new Pages project**:
- Go to Cloudflare Dashboard → Pages → Create a project
- Connect to the GitHub repo
- Build settings:
  - Framework preset: **None**
  - Build command: *(leave blank)*
  - Build output directory: `/` (or `.`)
- Under **Custom domains**: add `realtor510.com/east-bay-school-guide`
  — or point a subdomain like `schools.realtor510.com`

### 4. Update the canonical URL
Once live, confirm the canonical tag in the HTML matches the real URL:
```html
<link rel="canonical" href="https://realtor510.com/east-bay-school-guide">
```
If the final URL is different (e.g. a subdomain), update this line.

## One thing to note about email links
The nav "Contact" link uses `mailto:patrick@realtor510.com` directly.
The original realtor510.com site uses Cloudflare's email obfuscation
(`/cdn-cgi/l/email-protection`) — that only works on pages routed
through Cloudflare's proxy. The mailto: approach here is fine and
actually more universally compatible.
